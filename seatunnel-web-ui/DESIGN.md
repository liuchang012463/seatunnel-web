# SeaTunnel Web 桌面 UI 设计规范

视觉基准来自总集提供的 Aircas Vue 模板和 Open Design 生成的 `aircas-preview`。对照时以预览的「规范样例」「控件与表单」为主。持有本地预览时，可在桌面 Chromium 打开仓库 `tmp/aircas-preview/index.html`。预览、截图和 Vue 源码不属于 React 应用。已定样式用本规范与预览核对，未定的布局与交互再用 Open Design 探索。

迁移只对齐视觉和交互反馈，沿用 React、Ant Design 5、现有桌面布局和业务组件。不移植 Vue 或 Element Plus 样式，不改变路由、接口、权限、数据流和业务操作。Aircas 参考与既定项目规范冲突时，按本文的 React 规则执行。

## 主题与背景层级

默认使用暗色值班台。浅色数值用于维护现有令牌和对照，不代表本次试点要开放主题切换。保留项目现有主题初始化和 `data-st-theme` 机制，不复制 Vue 的主题切换方式。

## 字号、尺寸与桌面布局

- 默认字体为 Microsoft YaHei，依次回退到 Helvetica、Arial、sans-serif。保留既有标题层级，重要功能标题采用 `20px`，面板及弹窗标题通常采用 `16px`。**所有可见文字至少 `14px`**，包括辅助说明、标签、表格和按钮。Vue 样例的 `12px` 辅助字号不迁入，内容放不下时先调整布局或留白。
- 普通单行输入默认 `30px`，普通按钮 `32px`，不强行同高。基础圆角 `6px`，小圆角 `3px`，大圆角 `10px`，滚动条 `6px`。间距以 Aircas 的 `4 / 8 / 12 / 16 / 24px` 为参考，优先复用已有组件间距，不覆盖已确认的业务布局。
- 新建页面的主内容直接从必要的工具栏、筛选区或业务面板开始。不另加主标题、解释性副标题或说明段落，不添加与标题并列的「返回概览」，也不留空标题行。面板、表格和弹窗内的功能标题按需保留。左侧品牌名下不放说明文案，必要提示放到对应控件或内容区域。
- 页面、面板、页签不添加装饰性英文眉题或与中文标题重复的英文说明，如 `CATALOG`、`INSPECTOR`、`SAMPLE DATA`。业务标识和必要技术术语（含表名、字段名、FQN、Schema 等）保留。清理时检查受影响的各页签，移除渲染节点和占位空白。
- 保留已有顶栏、可折叠侧栏和导航。目录、列表、详情等主内容边框面板默认填满扣除工具栏和留白后的窗口剩余高度，同排面板上下边界对齐，不随少量内容或空结果收缩。指标卡、按钮和弹窗按各自用途确定高度。
- 用 Flex/Grid 分配可用高度，不用固定最小高度模拟撑满。内容超出时在面板内部滚动。较窄电脑窗口需要换行时，保留合理的面板高度和页面滚动。项目仅覆盖电脑端，不设计或验证手机、平板布局。

## React 组件与交互状态

| Aircas 参照 | 本项目复用 | 对齐规则 |
| --- | --- | --- |
| 按钮 | Ant Design `Button` | 保留普通、主操作、轻量和禁用层级。暗色主按钮常态 `#126681`、悬停 `#197F9E`、按下 `#093D7E`。 |
| 表单、输入、选择、日期、开关、树 | `Form`、`Input`、`Select`、`DatePicker`、`Switch`、`Tree` | 暗色聚焦用 `#00C4E5`。校验错误、警示和禁用应能与普通焦点区分，保留现有键盘操作与校验逻辑。 |
| 输入字数提示 | `Input`、`Input.TextArea` | 对已有字数上限的字段，在控件旁显示「当前字数 / 上限」，计数与提交校验使用同一口径。验收输入、粘贴和到达上限；若允许暂时超限，另用文字说明校验错误，不只改变计数颜色。 |
| 行内提交反馈 | `Form`、`Button` 与表单内状态区 | 在提交按钮附近显示提交中、成功或失败。提交中防止重复提交，结果可被读屏感知。失败时保留已填内容并说明下一步，不只靠全局消息反馈。 |
| 表格与分页 | `Table`、`Pagination` | 表头使用标题色带，文字至少 `14px`。选中行优先于悬停和斑马纹，固定列使用同一状态的不透明底色。现有排序、筛选和分页行为不因样式变化而改变。 |
| 表格长文本悬浮提示 | `Table` 单元格与 `Tooltip` | 仅在内容实际被省略时，通过鼠标悬停或键盘聚焦显示完整原文，不增加表格行高。验收列宽变化前后的完整值和截断值，不为可完整读到的内容重复显示提示。 |
| 对话框与确认框 | `Modal`、既有确认框 | 暗色标题带 `#0E5C78`，正文 `#000F23`。保留遮罩、关闭、键盘和焦点行为。Vue 样例的 `560px` 宽仅供参考，不统一改写业务弹窗宽度。 |
| 抽屉 | `Drawer` | 参照右侧展开、暗色面板底和独立标题区，不套弹窗色带。`440px` 是 Vue 样例尺寸，既有业务抽屉按内容保留宽度。 |
| `AircasPanel`、`AircasLoading` | 既有面板或 `Card`、`Spin`、`Empty` | 保留背景分层和清楚的加载、空态、失败反馈。不新增仅在 Vue 演示出现的最小化、恢复和关闭操作。 |
| 状态标签 | 既有 [StatusChip](./src/components/StatusChip.tsx) | 用状态点和可读中文文字共同表达成功、警示、失败、处理中或中性状态，不另造一套业务状态色。 |
| 时间轴与图表 | 既有 React 业务组件和图表配置 | 以预览核对视觉层级和状态呈现，保留真实数据、筛选和更新机制，不使用静态截图替代。 |
| 图表错误提示 | 图表面板内的 `Alert` | 取数、初始化或渲染失败时，在图表所在面板明确说明错误；可以恢复时提供就地重试。验收失败和重试，确保错误与加载、无数据状态可区分。 |

### 表格分页与内部滚动

- 填满剩余高度的列表面板中，分页始终可见，固定在面板底部右侧，不随行数、筛选或空状态移动。把表格内容滚动区与分页分开，标题与分页不参与压缩。
- 用 Flex/Grid 传递剩余高度。检查 `.ant-table-wrapper`、`.ant-spin-nested-loading`、`.ant-spin-container` 等中间容器是否允许收缩，例如使用 `flex: 1` 和 `min-height: 0`。只在表格内容区域开启滚动，页面特定布局不改全局表格规则。
- 核对零条数据时组件的实际渲染。需要始终显示分页而组件未渲染时，用禁用分页保持位置、留白和总数一致，不与非空分页重复。验收包含多条、单条、空数据及滚动前后，确认分页稳定且内容仍可访问。

## React 实现入口

- [`src/app.tsx`](./src/app.tsx) 的 `rootContainer` 挂载 [`ThemeConfigProvider`](./src/components/ThemeConfigProvider.tsx)，由它统一应用 Ant Design 主题算法和运行时令牌。
- [`src/styles/theme-tokens.ts`](./src/styles/theme-tokens.ts) 负责构建配置与运行时共用的暗、浅主题基础颜色和几何令牌。参与 Ant Design 颜色派生的令牌使用实际色值。
- [`src/design-system.less`](./src/design-system.less) 管理业务 CSS 使用的 `--st-*` 语义变量和存量样式兼容。公共视觉从此复用，不在各页面散落重复颜色值。
- [`src/styles/antd-theme.ts`](./src/styles/antd-theme.ts) 将语义变量映射到 Ant Design 组件令牌。只有直接绘制的属性才引用 CSS 变量。确有存量强覆盖时，在其后加载的 [`src/styles/antd-components.less`](./src/styles/antd-components.less) 做最小兼容补充。
- 旧代码注释中的 `DESIGN.md §…` 指向历史文档编号，不是本文的章节索引。

## 试点与验收

建议以「数据源管理」的**列表视图**（`/data-source`）试点。该页已有筛选、表格、独立分页和新增／编辑弹窗。先用 Aircas 预览逐项比较，区分现有主题已覆盖、页面覆盖和共享缺口。列表空态须保留面板和禁用分页，分页位置由页面布局负责。

共享令牌能解决且确属跨页的差异，确认受影响页面后才调整共享层，并回归另一处使用同一组件的典型页面。只在试点出现的差异，改该页的布局或样式。不因试点预先重写主题或其它业务页。

修改主题时验证令牌类型和构建。使用 Chrome dev 或 Playwright 在常用桌面窗口核对真实流程，包括使用筛选、切换列表视图、打开和关闭新增或编辑弹窗。另检查按钮状态、表单焦点及错误／禁用、表格固定列和选中态（如页面已有）、空态、分页、键盘可操作性及溢出遮挡。组件隔离页和模拟数据验证要与真实页面验收分别说明。试点验收后，再按影响范围逐页推广。

## 数据可视化大屏

大屏案例的字号、配色和间距只用于大屏，应按实际显示设备和观看距离验证，不覆盖上述桌面业务组件规范。

以 PxCook 中的《数据可视化首页（大字版）设计控件》为案例，复盘了 00–17 共 18 张画板。适用场景为服务大厅公示屏、运营值守屏和会场展示屏。画板尺寸、色值和字号来自设计稿，现场可读性需要用实际设备和观看位置验证。

### 1. 按观众要做的判断排版

| 场景 | 观众优先要知道什么 | 可参考的画板 |
| --- | --- | --- |
| 大厅公示 | 现在等多久、轮到谁、去哪个窗口、服务是否有变化 | 00 社区便民服务总览、17 叫号与告警 |
| 运营值守 | 当前量有多大、相对目标差多少、哪些事项要处理 | 16 运营总览、03 构成与达标 |
| 会议展示 | 变化往哪走、和哪个时期比、什么因素贡献最大 | 02 趋势与周期、03 构成与达标 |

00 的总览画板为 **1920 × 1080（16:9）**。页眉给出主题和更新时间，首排四张卡回答「现在怎样」，中间用较宽的七日趋势回答「最近怎么变」，右侧用比例条回答「业务从哪里来」，底部收纳服务提示。可以沿用这种阅读顺序，并按屏幕用途调整优先级。大厅公示把等待时间、叫号和窗口变动放在远处就能看到的位置。运营值守把偏离目标和待处理数量放到首排。16、17 是组件组合示例，画板尺寸各自不同。

首屏信息可以分三层。远处先能认出主指标或异常。走近后能读出数值、单位、目标和更新时间。细看时能查到图表口径、来源和少量记录。主图优先占宽，告警有固定区域，公告可以更新而不推动关键内容移位。

### 2. 让指标本身足以支持判断

01 的卡片结构是「名称 → 大数值和单位 → 一行解释」。四类解释都适合复用：较基准变化多少、距离目标多远、影响范围是什么、数据何时更新。

| 设计稿中的例子 | 复用时怎么写 |
| --- | --- |
| 服务人次 1,284，比昨日多 96 人次 | 写明比较是否为昨日同一截止时刻。未结束的今日与昨日整日并列时，应标出不同的统计窗口。 |
| 完成率 73%，目标 90%，配绿色勾（01、16） | 主值旁显示「距目标 17 个百分点」。颜色和符号根据达标规则产生。如果当天仍在统计，区分「当前进度」与「到考核时点仍未达标」。 |
| 平均等候 12 分钟，底部又写当前预计等候 12 分钟（00） | 「今日平均」描述已发生的等待，「当前预计」指导正在排队的人。两项若并列，分别标注，并定义「目标 15 分钟」适用哪项。 |
| 已办 936 件、服务 1,284 人次、今日办理进度 73%（00） | 为比率标清分子、分母和统计范围。相邻的件数与人次不一定属于同一统计口径。 |

一张指标卡交付前，补齐名称、单位、统计范围、时段、数据更新方式、比较基准和异常触发条件。用长数字和长标签检查布局，确保数位变化后单位仍紧贴主值。遇到真实零值显示 0，未知或取数失败使用文字说明。

### 3. 先确定要比较的对象，再选图

| 要回答的问题 | 图形与读法 | 关键标注 |
| --- | --- | --- |
| 过去几天往哪变？ | 折线，00 用低亮度面积衬托趋势 | 时间范围、单位、最新值。点较少可全标，点密时只保留最新、峰谷和异常。缺测段留断点。 |
| 每个周期有多少？和同期差多少？ | 单柱或分组柱，使用共同的零基线 | 本期与对照期的具体日期、等长区间和统一单位。 |
| 每天的总量由什么组成？ | 03 的堆叠柱同时展示总量和构成 | 各分项应互斥并可加总。要精确比较某个分项时，优先用共享基线的分组柱。 |
| 这个整体如何分配？ | 00、03 的 100% 横条，旁边直接列名和百分比 | 写清整体是什么。未知分类单列，取整后若有尾差，按统一规则处理。 |
| 离目标还有多远？ | 03 的同尺度进度条加独立目标线 | 同时写实际值和目标。例：68%，目标 75%，差 7 个百分点。 |
| 谁排在前面？ | 04 的降序横条，或 11 的「名次＋名称＋数值」 | 写明排行指标、单位和时段。绝对量排行使用共同的数值轴，可去掉像「未完成部分」的背景轨道，以区别百分比进度。 |

00 的三项渠道占比通过色块显示大致份额，右侧再给出类别和精确数值，两层信息互相校验。07–10 有筛选、分页、图例与单点明细。用于值守时，选中条件和统计时段应始终可见，核心读数应直接露出。长明细用固定行数和页码，轮播可暂停，告警与叫号期间保留关键信息。

### 4. 把告警、业务状态和数据状态分别设计

- **业务状态**。06 的正常、需关注、异常同时用颜色、文字和符号。黄、粉红分别承担关注和告警时，当前值、对照组和阈值线要靠标签或形状辨认。05 的「预计等候时间超过 15 分钟」比单独显示黄色条更明确。
- **数据状态**。05 给出了暂无数据、正在更新、离线三个状态。暂无记录要交代时段。更新中保留上一版有效值并标注更新时间。离线或超出数据有效期时标出「最近成功更新」，保留历史数据也要明示是旧值。局部异常就标在相关模块，全屏数据都过期才提升到全屏提示。
- **给现场观众明确去向**。17 的「A028 到二号窗口办理」与「二号窗口暂时停止办理」同屏，指令冲突。应以窗口可用状态为准，屏上只显示有效的当前叫号，并给替代窗口或等待指引。屏上警报至少交代受影响对象、当前情况和下一步。
- **减少状态间的竞争**。普通公告和成功反馈保持稳定，真实异常有固定位置和更强的文字层级。轮播或刷新时仍能看到有效告警，恢复后有清晰的状态切换。

### 5. 把原稿的视觉参数当作起点

| 项目 | 原稿参考 | 大屏设计做法 |
| --- | --- | --- |
| 字号与字重（15） | 关键数字 60 px，Inter Bold。大屏标题 52 px、区块标题 36 px、卡片标题 32 px，微软雅黑 Bold。正文 28 px、单位 26 px、坐标与辅助说明 24 px。 | 先验证主值、单位和告警文字，再定可留几张卡、几个刻度。信息放不下时优先减少内容。 |

### 6. 上屏验收

- 在目标设备全屏展示，从最远常用站位和侧方走动位置检查。请不了解稿件的人短时间看一眼，说出屏幕主题、主指标及其单位、当前有没有异常。大厅案例可再请实际年龄段的使用者看一遍。
- 用现场常见光照分别看正常、告警和离线。确认浅色正文、目标线和小字可读，关掉颜色提示后仍能靠文字与符号理解状态。电脑上的画板截图用于复盘设计，现场读屏结果用于确定最终字号、对比和内容容量。
- 用实际范围的极端值检查布局：最长服务名称、最大数值、零值、缺测、数据过期、窗口停用和多条告警并发。核对日期筛选切换后图例、数值和统计范围一起更新。
- 验收叫号与告警同时发生的情形。观众能回答「轮到谁、去哪儿、当前还能不能办理」，值守人员能区分业务异常与数据失联。
