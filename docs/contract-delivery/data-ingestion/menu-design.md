# 数据采集引接软件一、二级菜单设计

## 1. 文档定位

本文档定义数据采集引接软件的一级、二级菜单信息架构，并将当前
SeaTunnel-Web 前端页面映射到新菜单。

本设计只确定导航结构、页面归属和复用关系，不代表所有规划菜单均已完成开发。
页面实现状态统一使用以下标识：

- `R-复用`：当前项目已有真实页面，原则上复用或改名，不新建同类页面。
- `A-改造`：当前项目已有页面或组件，需要调整入口、文案、字段或交互。
- `I-集成`：通过 TDuck、OpenMetadata 等外部系统的公开 API、SDK、事件或 WebHook 集成。
- `N-新建`：当前项目没有可承接的页面，需要新增。
- `L-有限实现`：按已批准的范围提供有限功能，不承诺完整平台能力。

## 2. 命名结论

原待定一级菜单 `XX` 建议命名为：

> **引接资源**

理由：

1. 数据源、SeaTunnel 执行引擎和数据探查都属于创建引接任务前需要准备的资源。
2. “引接资源”能够与“数据引接”的任务执行过程清楚区分。
3. 不使用“数据资源”，避免后续与数据资产、数据目录、入湖资源等概念混淆。
4. 后续增加连接器、驱动、资源组等页面时，仍可自然归入该一级菜单。

## 6. 外部系统页面展示方式

### 6.1 TDuck

“数据采报管理”应由本平台提供统一入口、登录态衔接和表单/批次/引接任务映射。
TDuck 保持表单与答卷事实所有权。

优先顺序：

1. 使用 TDuck 公开 API/WebHook，在本平台构建合同所需的轻量管理页。
2. 对暂时无法通过 API 完成的设计操作，使用带单点登录的外部页面跳转。
3. 只有在同源、安全策略和页面兼容性验证通过后才考虑 iframe，不将 iframe 作为默认方案。

### 6.2 OpenMetadata

“数据探查”和“数据拓扑管理”使用同一套 OpenMetadata 元数据事实：

- 数据探查侧重目录、表字段、画像、质量、分类和所有权；
- 数据拓扑侧重血缘、上下游依赖和影响分析；
- SeaTunnel-Web 负责将数据源、任务和运行实例标识映射到 OpenMetadata 实体；
- 不直接读写 OpenMetadata 内部数据库。

### 6.3 统一 SSO

SSO 不形成一级或二级业务菜单，统一作用于平台登录、菜单可见性和 API 访问控制：

- `/login` 改造成 SSO 登录发起/状态提示页，并新增隐藏的登录回调路由；
- 用户、组织、角色和人员权限由 SSO 统一维护，本项目不提供对应管理页面；
- TDuck、OpenMetadata 的人员访问优先接入同一 SSO，避免用户在三个系统分别维护账号；
- 现有本地用户数据如因历史外键必须保留，只作为 SSO 主体标识映射和显示缓存；
- 服务账号、边缘设备和数据源账号不使用人员 SSO 令牌，按独立安全方案管理。

## 7. 菜单与路由实施规则

1. 一级菜单只表达稳定业务域，创建、编辑、详情、配置、运行日志等页面均使用隐藏子路由。
2. 隐藏子路由必须设置面包屑，并保持对应二级菜单的选中状态。
3. 首期尽量保留现有 `/data-source`、`/client`、`/metrics`、`/alarm` 和 `/sync/**`
   路径，先调整菜单层级和名称，避免同时改动大量跳转逻辑。
4. 新路由使用业务语义，不在路径中直接暴露 TDuck、OpenMetadata 等产品名，便于未来替换实现。
5. `MOD-007 数据安全与 SSO 集成` 是横切模块。用户、组织、角色和人员权限统一来自 SSO，
   本项目不设置“用户管理”“角色管理”“权限管理”菜单，也不提供本地维护页面。
6. 菜单按 SSO 返回的角色/权限声明或统一授权接口控制：
   - 采报人员：数据采报；
   - 数据工程人员：引接资源、数据引接、入湖管理；
   - 运维人员：引接资源中的引擎管理、运行运维；
   - 系统管理员：由 SSO 授予对应权限后访问全部菜单，重点包括系统管理；
   - 查看人员：按授权只读访问引接态势、运行监控和数据拓扑。
7. 前端菜单显隐只用于交互，所有 API 仍必须校验 SSO 登录态和授权结果。
8. 现有用户表如因创建人、责任人或历史数据关联必须保留，只作为 SSO 主体映射/显示缓存，
   不得继续作为可人工维护的用户权限事实源。
9. 规划页面在功能未达到可用和可验收状态前不得开放空白菜单；确需演示时必须标注
   `L-有限实现` 范围。

## 8. 实施优先级

| 阶段 | 菜单实施范围 |
| --- | --- |
| M0 | 建立一级菜单骨架并接入 SSO 菜单授权；完成 TDuck、OpenMetadata 的 SSO 与菜单集成 PoC |
| M1 | 开放数据源管理、引擎管理、离线/实时引接、运行监控、告警管理；完成数据采报最小真实链路 |
| M2 | 开放采集报告、数据探查、引接链路、数据拓扑、引接态势、入湖资源和生命周期管理 |
| M3 | 按批准范围开放云边协同、边缘接入、故障辅助和逻辑入湖有限能力 |

## 9. 评审结论建议

本菜单方案建议作为后续原型和前端路由改造的基线，重点评审以下四项：

1. 是否确认使用“引接资源”作为待定一级菜单名称。
