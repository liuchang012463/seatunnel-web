# MOD-005 监控告警、态势与故障辅助

## 1. 目标

在现有状态、日志、指标和告警体系上形成统一态势、效率分析、执行时间线和规则型故障辅助。

## 2. 指标与投标模块映射

- 指标：F-03.02、F-03.06、F-09.01～F-09.02、F-11.01～F-11.03、P-05。
- 投标模块：任务实时监控告警、态势可视化、运行效率分析、采集操作记录、操作回放、故障定位与优化。

## 3. 当前能力和证据

- Job/Streaming Metrics Monitor 提供运行指标采集。
- 日志接口和实例状态可关联真实任务。
- AlarmController、AlarmRuleEngine 和告警插件提供规则、通道、投递与记录。
- 缺统一大屏、规范审计时间线、可视化回放和根因分类模型。

## 4. 实施边界

### Reuse

- 复用实例状态、日志、指标、WebSocket、告警规则/通道/记录。

### Modify

- 统一任务、实例、Engine Job、数据源和 traceId 关联。
- 增加历史聚合、效率指标和钻取链接。

### Add

- 态势大屏、时间线事件、故障分类规则和建议知识库。
- 告警时效基准和可观测失败队列。

### Integrate

- 可接企业消息/监控平台，但告警核心保持插件边界。

### Limited or Mock

- 回放只重放任务节点、状态、日志摘要和告警，不回放完整数据内容。
- 根因定位采用确定性分类和证据链接；自动修复仅允许批准的白名单动作。

### Out of scope

- 不构建通用 AIOps 平台。
- 不伪造无真实任务来源的生产指标。

## 5. 主要流程与接口边界

```text
Engine 状态/指标/日志
→ 平台关联任务与实例
→ 实时态势与历史聚合
→ 规则告警
→ 故障分类/建议
→ 时间线回放和人工处置
```

## 6. 依赖和实施顺序

- 依赖 MOD-003/MOD-004 产生真实运行数据。
- 先统一关联键和告警，再建设大屏、分析和回放。

## 7. 验收场景

- 批/流任务状态和指标实时显示并可钻取日志。
- 失败任务触发告警、形成记录并关联实例。
- 端到端告警满足最低/响应时效。
- 历史实例按时间线回放节点、状态、日志摘要和告警。
- 典型故障可分类到数据源、网络、Connector、Engine、目标或配置。

## 8. 风险与未验证项

- 外部告警通道网络时延是否计入 P-05 需确认。
- 运行指标长期存储量和保留周期。
- 操作/数据轨迹必须脱敏，并按 SSO 返回的人员权限执行后端访问控制。
