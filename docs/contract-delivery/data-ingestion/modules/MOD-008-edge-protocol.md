# MOD-008 云边同步与协议接入

## 1. 目标

以限定场景和明确协议完成云边同步、离线缓存、任务协同和轻量边缘接入 PoC，避免把 SeaTunnel-Web 扩展成通用边缘计算平台。

## 2. 指标与投标模块映射

- 指标：F-08.01～F-08.03、F-10.01～F-10.03、F-14.01～F-14.03。
- 投标模块：边缘采集缓存、云边数据同步、云边任务协同、协议解析/转换/版本/规则、轻量协议引擎、极简调度、边缘预处理和安全防护。

## 3. 当前能力和证据

- SeaTunnel-Web 可作为云端任务控制面并复用插件/Transform 思路。
- 当前仓库没有边缘 Agent、离线缓存、通用协议运行时或目标硬件证据。
- 所有本模块能力均需要专项 PoC，不能由 Web 页面 Mock 替代核心链路。

## 4. 实施边界

### Reuse

- 复用任务定义、配置、状态、告警和 Transform 的确定性转换模型。

### Modify

- 为任务增加边缘目标、配置版本和回传状态。
- 平台增加边缘节点、缓存和协议插件状态视图。

### Add

- 独立边缘 Agent：本地持久化队列、TTL、优先级、检查点、断点续传和幂等。
- 协议插件 SPI、规则/版本注册和固定算子预处理。

### Integrate

- 优先选择成熟消息/边缘组件和协议 SDK；具体产品在 PoC 后决定。
- 安全能力依赖 MOD-007 的证书和密码产品。

### Limited or Mock

- M3 只承诺一个指定边缘环境和 1～2 个明确协议的 V1/R 组合。
- 资源利用率、低功耗和复杂作战场景只按可测硬件指标展示。

### Out of scope

- 不承诺未知协议自动识别。
- 不建设通用 IoT/边缘编排平台。
- 不在没有设备和阈值时宣称低功耗达标。

## 5. 主要流程与接口边界

```text
平台下发签名任务/配置
→ 边缘 Agent 校验并执行
→ 协议插件解析/预处理
→ 本地持久化缓存
→ 在线增量上传或离线等待
→ 云端确认检查点和状态
```

## 6. 依赖和实施顺序

1. 取得硬件、操作系统、网络和协议样例。
2. MOD-007 确定设备身份和链路安全。
3. 先做缓存/续传，再做任务协同和协议扩展。

## 7. 验收场景

- 云端下发任务、边缘确认/执行/失败并回传状态。
- 断网期间数据持久化，恢复后不重不漏。
- 缓存容量、TTL、优先级和清理可验证。
- 指定协议完成配置、解析、转换、版本回滚和错误隔离。
- 指定设备上记录 CPU、内存、网络和功耗/续航指标。

## 8. 风险与未验证项

- 目标设备、网络、协议、功耗阈值均未给出。
- 边缘 Agent 语言、升级方式和供应链安全未选择。
- 跨平台文件系统与消息顺序语义可能显著增加工作量。
