# MOD-009 入湖资源与数据生命周期

## 1. 目标

在物理入湖主链路之外，提供数据湖资源维护、离线文件接入、有效期/暂存周期策略，以及经过明确限制的逻辑入湖能力。

## 2. 指标与投标模块映射

- 指标：F-06.02、F-15.01～F-15.03、P-02，并承接 F-04 的资源生命周期部分。
- 投标模块：数据逻辑入湖、数据对账、采集数据时效校验、暂存周期、时效策略和离线文件导入。

## 3. 当前能力和证据

- SeaTunnel Transform/Source/Sink 可支撑规则过滤和物理搬运。
- OpenMetadata 可支撑逻辑元数据映射、新鲜度和质量上下文。
- 当前无联邦查询引擎、统一有效期策略、合同级离线文件导入器。

## 4. 实施边界

### Reuse

- 复用数据源、Transform、任务调度、OpenMetadata 资产和质量信息。

### Modify

- 在任务配置中引用有效期/暂存策略，并记录命中统计。
- 在数据湖资源视图中关联数据源、目标、模型和生命周期。

### Add

- 轻量策略模型：作用域、条件、有效期、动作、版本和审计。
- 离线文件上传、解析、校验、批次、进度、失败明细和重试。
- 数据对账和到期/清理统计。

### Integrate

- 逻辑入湖若要求真实联合查询，专项选择数据虚拟化/联邦查询组件。
- Word/PDF/SQL/DMP 解析采用成熟解析库或专用工具，不重复自研格式解析器。

### Limited or Mock

- 一期逻辑入湖只做跨源元数据映射、授权入口和限定数据集访问 V1。

### Out of scope

- 不把 OpenMetadata 元数据查询描述成业务数据联合查询。
- 不在没有样例时承诺任意 DMP/Word/SQL 文件。
- 不直接删除超过有效期的生产数据，先支持标记/隔离和审批。

## 5. 主要流程与接口边界

```text
上传/在线数据
→ 解析与 Schema 校验
→ 有效期/暂存策略
→ SeaTunnel 物理入湖或逻辑映射
→ 对账、统计、到期动作和审计
```

## 6. 依赖和实施顺序

- 依赖 MOD-002 的资产映射、MOD-003 的物理入湖和 MOD-007 的 SSO 授权校验。
- 先取得离线样例并完成解析 PoC，再确定是否需要联邦查询组件。

## 7. 验收场景

- Excel/DMP/Word/SQL 样例上传、解析、校验、进度、错误和重试。
- 最低/响应文件大小和时间分别测试。
- 按数据源、类型、部门配置有效期并验证正常/临界/过期行为。
- TTL、容量、清理和保留例外形成审计。
- 逻辑映射能从统一入口定位到授权数据源；若有联邦查询，则单独 E2E。

## 8. 风险与未验证项

- DMP/Word/SQL 的格式定义和验收样例缺失。
- 自动清理涉及不可恢复数据操作，必须审批和可回滚。
- 引入联邦查询组件可能显著增加部署和维护成本。
