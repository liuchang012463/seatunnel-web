# MOD-001 数据采报与采集报告

## 1. 目标

以 TDuck 社区版为表单采报主干，补齐采集任务分配、统一上报状态和必要的报告能力，避免在 SeaTunnel-Web 中重新开发表单设计器。

## 2. 指标与投标模块映射

- 指标：F-01.01～F-01.07、F-05.01～F-05.03。
- 投标模块：表单模板定制、表单数据校验、智能校验引擎、数据填报及导入导出、智能采集任务分配、采集引接模式设计、典型场景适配、采集报告管理。

## 3. 当前能力和证据

- SeaTunnel-Web：有自动引接任务、状态和调度，不具备表单采报主干。
- TDuck 社区版候选：拖拽表单、27+ 组件、显隐逻辑、答卷增删改/导出/打印/预览、基础图表、模板中心、全量同步 API 和增删改 WebHook。
- 状态：拟集成，尚未完成社区版 API、统一 SSO 衔接、前端源码和数据规模 PoC。

## 4. 实施边界

### Reuse

- 复用 SeaTunnel-Web 的自动引接任务、调度、状态、日志和告警。
- 复用 TDuck 的表单设计、发布、填写、答卷和基础统计能力。

### Modify

- 在平台增加 TDuck 外部表单、答卷批次、采报任务和引接任务映射。
- 增加采报状态、责任人、催办和上报结果的统一视图。

### Add

- API/WebHook 适配器、签名校验、幂等键、检查点、重试和失败队列。
- 规则型任务分配、逾期提醒和基础审核状态。
- TDuck 不覆盖的报告生成、受控分发和操作审计。

### Integrate

- TDuck 社区版。
- 若 Word/PDF 复杂版式是硬验收，集成轻量模板报告库。

### Limited or Mock

- 语义纠错采用领域词典、确定性规则和人工确认 V1。
- 报告分析采用确定性统计，不建设通用 BI/AI 报告平台。

### Out of scope

- 不复制 TDuck 表单设计器。
- 不把 TDuck Pro/TDuckX 能力当成社区版能力。
- 不承诺通用语义理解、自动无人工纠错或未定义准确率。

## 5. 主要流程与接口边界

```text
平台创建采报场景
→ TDuck 创建/发布表单
→ 用户填写或批量导入
→ TDuck WebHook/API
→ 平台记录批次并触发 SeaTunnel 引接
→ 入湖结果回写采报任务
→ 报告生成/导出/分发
```

TDuck 是表单与答卷事实来源；平台只保存外部 ID、批次、责任、状态和必要摘要，不直连 TDuck 数据库。

## 6. 依赖和实施顺序

1. MOD-007 完成人员 SSO 衔接、服务认证和密钥策略；TDuck 不单独维护人员用户和角色事实。
2. M0 完成 TDuck PoC 和版本冻结。
3. 先交付表单→答卷→引接闭环，再补任务分配和报告。

## 7. 验收场景

- 创建、发布、复制和版本化表单并完成真实填写。
- 合法/非法答卷触发预期校验。
- 单条、批量、导入、导出和上报状态可追踪。
- WebHook 重复、乱序、失败重试不产生重复引接。
- 手动、批量、定时生成报告并完成四种格式/分发验收。

## 8. 风险与未验证项

- 社区版前端源码、统一 SSO 衔接、授权声明消费、跨字段校验和批量导入边界。
- DMP/Word/SQL 文件不应在未验证时承诺由 TDuck 直接导入。
- 报告模板复杂度可能使轻量自研失控，需先取得样例。
