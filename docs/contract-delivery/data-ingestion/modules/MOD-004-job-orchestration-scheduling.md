# MOD-004 引接任务编排与调度

## 1. 目标

复用现有批/流、单表/多表/脚本和调度能力，形成合同口径的任务配置、策略编排、批量控制和容量管理。

## 2. 指标与投标模块映射

- 指标：F-03.01、F-03.03～F-03.05、F-03.07、P-03。
- 投标模块：引接任务配置管理、引接任务调度、批量任务作业、单任务多表同步、引接策略配置。

## 3. 当前能力和证据

- Batch/Streaming Job Definition 已提供 single、multi、script 模式。
- 前端工作流、HOCON Builder、cron 预览和调度生命周期已存在。
- 存在批量创建、执行和暂停接口。
- 未验证 1500 个在线任务管理容量及 P95 启动时间。

## 4. 实施边界

### Reuse

- 复用任务定义、版本、调度、执行、暂停、日志、指标和 HOCON。

### Modify

- 统一合同术语和批/流任务入口中的策略说明。
- 补场景模板、批量参数和任务汇总。

### Add

- 性能容量测试、任务分层查询和必要的批量操作保护。
- 合同指标到任务/实例的追踪标识。

### Integrate

- 无新增调度平台；沿用现有调度能力。

### Limited or Mock

- 实时任务通常为常驻 Streaming；“周期实时任务”按明确场景处理，不制造无意义调度。

### Out of scope

- 不复制一套任务模型。
- 不把网络主备切换归入普通 cron 调度。

## 5. 主要流程与接口边界

```text
选择数据源和模式
→ 配置 single/multi/script DAG
→ 校验并生成 HOCON
→ 保存/发布
→ 立即或 cron 调度
→ 批量执行/暂停
→ 实例和日志回查
```

## 6. 依赖和实施顺序

- 依赖 MOD-002 数据源和 MOD-003 Connector。
- 先回归现有模式，再做合同语义和容量优化。

## 7. 验收场景

- 三种模式创建、保存、编辑、复制和重新运行。
- 单任务同步多表并生成正确目标路由。
- 批量创建/执行/暂停和状态查询。
- 周期任务预览、启动、停止和触发记录。
- 按统一口径验证 ≤3秒/1500任务响应目标。

## 8. 风险与未验证项

- “管理 1500 任务”与“并发运行 1500 任务”必须区分。
- 当前 UI 中仍可能存在新旧 API/类型定义并存，需要设计阶段清理证据。
