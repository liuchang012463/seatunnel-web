# MOD-006 引接链路与数据拓扑

## 1. 目标

以现有批/流任务为真实链路执行事实，以 SeaTunnel DAG 和 OpenMetadata 血缘形成统一链路、路由、健康和拓扑视图。

## 2. 指标与投标模块映射

- 指标：F-12.01～F-12.03、F-13.02～F-13.03。
- 投标模块：引接链路配置、链路动态调度、链路性能优化、引接流向感知、拓扑智能构建、拓扑可视化管理。

## 3. 当前能力和证据

- `batch-link-up`、`stream-link-up` 已表达源、目标、字段映射、任务状态和 DAG。
- OpenMetadata 支持表/字段/管道血缘和影响分析，但尚未集成。
- 当前 `develop` 分支没有独立链路管理模块，历史方案只能作为规划参考。

## 4. 实施边界

### Reuse

- 复用批/流任务定义、DAG、状态、指标、调度和配置页面。
- 复用 OpenMetadata 血缘和资产关系。

### Modify

- 增加统一链路语义和跨批/流的查询/聚合视图。
- 发布任务时生成稳定链路 ID、任务版本和血缘事件。

### Add

- 链路摘要、主/备/优先级等业务属性扩展。
- SeaTunnel DAG 到 OpenMetadata lineage 的映射与重放。
- 拓扑筛选、状态着色、版本和资产/实例钻取。

### Integrate

- OpenMetadata REST/SDK/OpenLineage 能力。
- 网络主备状态通过基础设施 API/事件接入。

### Limited or Mock

- 任务级动态调度真实执行。
- 网络主备切换和带宽控制一期只消费基础设施结果或进行受控演示，不由应用伪实现。
- 性能优化采用规则建议和人工确认。

### Out of scope

- 不复制批/流任务执行模型。
- 不把 SeaTunnel env 参数描述成真实网络 QoS。
- 不直接控制交换机、路由器或 SDN，除非已有正式接口和授权。

## 5. 主要流程与接口边界

```text
批/流任务发布
→ 生成链路 ID 与不可变任务版本
→ 解析 DAG/源/目标
→ 发布 OpenMetadata 血缘
→ 汇聚任务与基础设施状态
→ 链路/拓扑视图
```

## 6. 依赖和实施顺序

- 依赖 MOD-002 的 OpenMetadata 和 MOD-003/MOD-004 的真实任务。
- 先实现统一只读链路视图，再增加策略属性和受控动作。

## 7. 验收场景

- 从统一入口查看离线/实时链路及真实任务绑定。
- 展示物理路由、逻辑映射、健康、吞吐和告警。
- 发布任务后自动生成源→处理→目标血缘和版本化拓扑。
- 拓扑可筛选、钻取到资产、任务、实例、日志。
- 任务级调度真实执行，网络级能力明确显示来源和状态。

## 8. 风险与未验证项

- 链路与任务是否一对一需要在详细设计阶段锁定。
- OpenMetadata 血缘实体和 SeaTunnel DAG 的版本/删除语义。
- 基础设施缺少 API 时不能承诺自动主备切换。
