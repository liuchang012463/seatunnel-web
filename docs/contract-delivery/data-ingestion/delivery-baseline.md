## 2. 目标和原则

本基线以满足验收、快速交付和减少开发工作量为目标，采用以下顺序：

```text
直接复用 → 小幅改造 → 集成成熟开源 → 简单自研 → 有限实现 → 展示/Mock
```

交付等级：

- `L1`：核心真实能力，必须可操作、可运行、有结果、可验证。
- `L2`：真实支撑能力，允许简化界面、固定流程或缩小配置范围。
- `L3`：展示或概念能力，允许受控模拟、固定规则或设计占位。

证据等级：

- `R`：真实实现。
- `V1`：真实控制流程加受控模拟或固定规则。
- `V2`：展示或设计占位。

强约束：L1 不使用纯 Mock 或 V2；无法确定真实方案时进入评审清单，不伪装成已满足。

### 2.1 SSO 前置约束

- 用户、组织、角色、人员权限和登录认证统一以既有单点登录（SSO）系统为权威源。
- 本项目不自建用户中心、角色中心、权限配置中心，不维护独立的人员密码。
- SeaTunnel-Web 现有本地用户、登录和权限代码只作为待适配存量能力，不再作为正式身份主数据。
- 如业务表必须保存创建人、责任人等关系，只保存 SSO 不可变主体标识及必要显示快照；
  不允许通过本项目页面手工新增、修改或删除用户和角色。
- 后端必须校验 SSO 登录态和授权结果；前端菜单隐藏不能替代后端鉴权。
- 服务账号、边缘设备身份、数据源凭据、证书和密钥不属于人员 SSO 范围，仍按 MOD-007
  的服务到服务认证与安全方案实施。

## 4. 当前系统结论

### 4.1 可优先复用的真实代码能力

| 能力 | 当前证据 | 结论 |
| --- | --- | --- |
| 数据源增删改查、连接测试、批量测试、驱动上传 | `DataSourceController`、数据源插件体系 | 可作为数据源管理主干 |
| 关系库、Kafka、CDC 接入 | JDBC/MySQL/Oracle/PostgreSQL/Doris/Kingbase/Dameng/Kafka 及 MySQL/PostgreSQL CDC 插件 | 复用，新增类型按插件流程扩展 |
| Catalog/Schema/Table/Column、预览等元数据访问 | `DataSourceProcessor`、各数据源 Catalog | 支撑基础探查，通用治理交给 OpenMetadata |
| 批任务和实时任务 | batch/streaming definition，single/multi/script 三种模式 | 复用任务配置主干 |
| 多表任务与图形化配置 | Guide Multi、工作流页面、HOCON Builder | 复用并做合同语义改造 |
| 调度、批量执行/暂停 | 调度 API、Quartz cron、批量执行接口 | 复用，性能容量需实测 |
| 状态、日志、指标 | Job/Streaming Metrics Monitor、日志接口、WebSocket | 复用监控数据源 |
| 告警规则、通道和记录 | `AlarmController`、`AlarmRuleEngine`、告警 SPI | 复用，补验收时效测试 |
| 本地登录、用户会话和用户相关代码 | Login/User 相关前后端代码 | 不作为正式用户权限主干；改造为 SSO 跳转、回调、会话和主体映射 |

上述结论表示当前代码存在真实实现，不表示本轮已完成生产环境、SeaTunnel Engine 或性能验收。

### 4.2 主要缺口

- 当前仓库没有表单采报、报告模板和采报审核主干。
- 当前分支没有独立的 `seatunnel-web-link-management` 模块；历史设计不能作为已实现证据。
- 文件夹增删改实时同步、边缘离线缓存、云边任务协同尚无完整实现证据。
- 逻辑入湖所需的数据虚拟化/联邦查询能力不是 SeaTunnel 的职责。
- 通用协议解析、协议版本管理、低功耗边缘运行时不是当前 Web 项目能力。
- 语义智能纠错、可视化操作回放、自动根因诊断和自动修复没有可直接验收的成熟实现。
- 所有性能响应值缺少本轮可复现的基准测试证据。
- 当前本地登录、用户和权限模型尚未完成 SSO 协议、主体标识、权限声明、退出和失效机制适配。

## 5. 外部组件决策

### 5.1 OpenMetadata：数据探查与元数据权威

- 状态：拟集成，尚未完成版本冻结和 PoC。
- 官方仓库：[open-metadata/OpenMetadata](https://github.com/open-metadata/OpenMetadata)
- 许可证：Apache-2.0。
- 当前官方说明覆盖数据库/Schema/表/字段元数据、搜索、画像、质量、血缘、所有权、分类，以及 API、SDK、事件和大量连接器。
- 本项目职责：
  - 统一数据资产目录和多源元数据探查；
  - 表/字段画像、质量结果和血缘展示；
  - 为数据源清查、拓扑和影响分析提供元数据事实。
- 明确不承担：
  - 实际数据全量/增量搬运；
  - 物理入湖；
  - SeaTunnel 任务执行和运行状态控制。
- 集成方式：优先使用 OpenMetadata Ingestion、REST API、SDK、事件或 WebHook；禁止直接读写其内部数据库。

### 5.2 TDuck 社区版：数据采报入口

- 状态：拟集成，尚未完成社区版前后端边界、鉴权和接口 PoC。
- 官方仓库：[TDuckCloud/tduck-survey-form](https://github.com/TDuckCloud/tduck-survey-form)
- 许可证：MIT。
- 仓库当前说明提供拖拽表单、27+ 组件、显隐逻辑、数据新增/编辑/导出/打印/预览、基础图表、模板中心、私有化部署、全量同步 API 和增删改 WebHook。
- 本项目职责：
  - 表单模板设计、发布和人工填报；
  - 表单结果管理、基础校验、导出和简单统计；
  - 通过 API/WebHook 将采报数据交给引接平台。
- 明确不直接承诺：
  - 企业级 RBAC 和多级审核；
  - 语义 AI 纠错；
  - DMP/Word/SQL 全格式批量导入；
  - 合同要求的全部报告格式和分发能力；
  - 复杂任务智能分配。
- 集成方式：TDuck 保持表单/答卷事实所有权；SeaTunnel-Web 保存外部表单、批次和任务映射；通过 API/WebHook 交换，不直连 TDuck 内部表。

### 5.3 统一 SSO：人员身份与权限权威

- 状态：确定集成；SSO 产品、协议和环境参数尚待项目接入资料冻结。
- SSO 职责：
  - 用户、组织、角色和人员权限主数据；
  - 用户登录、退出、会话失效和身份生命周期；
  - 向 SeaTunnel-Web 提供稳定主体标识和授权结果。
- SeaTunnel-Web 职责：
  - 适配 SSO 登录跳转、回调、令牌/会话校验和退出；
  - 使用 SSO 主体标识记录创建人、责任人、审批人和审计人；
  - 按 SSO 返回的权限声明或统一授权接口执行后端访问控制；
  - 对 TDuck、OpenMetadata 的人员访问提供统一登录衔接。
- 明确不实现：
  - 本地用户、组织、角色和人员权限的增删改查；
  - 本地密码认证、找回密码和人员账号生命周期；
  - 与 SSO 并列的第二套人员权限事实源。
- 不在 SSO 范围：
  - SeaTunnel-Web 与 Engine、TDuck、OpenMetadata 之间的服务身份；
  - 边缘终端/设备证书；
  - 数据源账号、密钥和证书。

## 7. 交付分期

### M0：先决条件与 PoC

1. 冻结 SeaTunnel 2.3.13、OpenMetadata、TDuck 和数据库/中间件版本。
2. 冻结 SSO 协议、客户端、主体标识、组织/角色/权限声明、退出和会话失效接口。
3. 完成 SeaTunnel-Web 现有登录/用户模型到 SSO 的适配 PoC，确认不保留本地用户权限管理入口。
4. 完成 TDuck API/WebHook、SSO 衔接、数据模型和社区版源码边界 PoC。
5. 完成 OpenMetadata 数据库连接器、画像权限、SSO 衔接、REST API 和部署资源 PoC。
6. 明确国密、服务/设备身份鉴权、密钥托管和安全验收环境。
7. 建立六项性能指标的统一基准环境和数据集。

### M1：核心真实链路

1. TDuck 表单创建/发布/填报 → API/WebHook → 引接任务。
2. 数据源注册、连接测试、元数据浏览和 OpenMetadata 目录同步。
3. SeaTunnel 全量/增量、批/流、单表/多表和物理入湖。
4. 调度、日志、指标、告警和最小态势视图。

### M2：增强和合同化

1. 报告模板/生成/多格式输出的最小补齐。
2. 链路统一视图、DAG/血缘拓扑和运行效率分析。
3. 数据清查、有效期、暂存周期、离线文件和逻辑入湖有限能力。

### M3：高复杂度受控交付

1. 云边离线缓存和任务协同 PoC。
2. 协议插件框架与少量明确协议。
3. 边缘轻量运行时演示。
4. 固定规则的语义提示、故障建议和操作轨迹回放。

## 8. 架构与数据边界

```text
TDuck（表单/答卷事实）
        │ API / WebHook
        ▼
SeaTunnel-Web（数据源、任务、调度、状态控制面）
        │ HOCON / Client API
        ▼
SeaTunnel Engine（真实数据传输执行面）
        │
        ├──► 数据湖/目标库（业务数据事实）
        │
        └──► OpenMetadata（元数据、画像、质量、血缘事实）
```

控制规则：

- 外部系统只通过公开 API、SDK、事件或 WebHook 集成。
- TDuck、SeaTunnel-Web、OpenMetadata 分别保留自己的事实所有权。
- 人员身份与权限只以统一 SSO 为权威源；各子系统不得形成可独立维护的第二套人员账号和角色。
- SSO 人员身份与服务账号、设备证书、数据源凭据分开管理，不混用人员令牌执行后台任务。
- Web 连接测试不替代 Engine 真实 Source/Sink 验收。
- OpenMetadata 的目录/画像成功不替代物理入湖成功。
- 外部事件使用幂等键、检查点、重试和可观测失败队列。

## 9. 性能与验收

| 指标 | 最低基线 | 响应基线 | 当前状态 |
| --- | --- | --- | --- |
| 全量/增量在线引接 | ≥1000 / ≥500 条/秒 | ≥1500 / ≥700 条/秒 | 未基准验证 |
| 离线文件导入 | 100MB：Excel/DMP/Word ≤90秒，SQL ≤150秒 | 130MB：前者 ≤60秒，SQL ≤100秒 | 格式能力和性能均待 PoC |
| 启动时间/管理容量 | ≤5秒 / ≥1000任务 | ≤3秒 / ≥1500任务 | 未容量验证 |
| 增量发现 | 低实时 ≤10分钟，高实时 ≤5秒 | ≤6分钟 / ≤3秒 | CDC 可复用，文件场景待实现 |
| 异常告警 | ≤5秒 | ≤3.5秒 | 告警代码可复用，端到端时效待测 |
| 200字节结构化数据传输 | ≥100MB/s | ≥200MB/s | 高风险承诺，未基准验证 |

每项性能测试必须固定源/目标数据库、表结构、数据分布、网络、并发、批大小、持续时间、预热方式和测量点。测试结果分别报告最低基线和响应基线是否通过。

## 10. 风险与评审门

进入模块详细设计前必须处理 `review-checklist.md` 中的阻塞项，重点包括：

- TDuck 社区版与合同采报能力之间的差额；

- 文件夹增量同步、逻辑入湖和边缘/协议技术选型；
- 国密与 GJB 安全验收边界；
- SSO 协议、主体标识、权限声明、退出/失效以及 TDuck/OpenMetadata 的单点衔接方式；
- 六项响应性能值的可复现验证；
- 当前分支链路管理的真实范围；
- L3 能力的有限实现/Mock 是否获得项目和验收方内部批准。
