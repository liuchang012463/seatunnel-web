> 关联实施基线：`引接分系统_双模入湖_Codex实现设计_v1.4.md`  
> 前端：React 18 + Umi Max 4 + Ant Design 5 + Pro Components 2  
> 目标：给 Luna Max 提供可直接编码、可验收的页面与交互规范。

## 0.1 首版审核基线（2026-09-01）

本页面设计按提交 `5c528967`（及其父提交）审核；工作区尚未提交的代码不计入验收。首版运行边界如下：

- 数据库只考虑 MySQL **8.0.39**，不考虑 H2，也不以 H2 migration 或 H2 测试作为前端门禁。
- 不执行应用部署或发布；Web 使用 `.vscode/launch.json` 启动，运行时和 Maven/JDK 设置使用 `.vscode/settings.json`。
- Doris 真实验证只针对本机 `/mnt/lc/doris`，页面能力必须服从该环境的 Driver/网络事实；未验证的 PostgreSQL/Oracle 能力继续显示 disabled reason。
- 页面不保存或展示密码、Token、连接 JSON、内部策略快照 JSON 和完整 DDL；真实 API 异常以稳定 code/reason 和可重试状态呈现。

### 首版不应误读为完成的后端依赖

- MANAGED create 的 lifecycle binding 必须由后端在 Doris 调用前以同一短事务原子发布 mapping、binding 和 operation journal；preview 中携带策略不能替代该实现。
- Logical 页面中的 update/delete/refresh/reconcile 操作只有在对应 controller/service、状态机和测试提交后才可启用；当前入口若保留，应展示稳定 disabled reason 或等待接口接通。
- 结构化单表/JOIN 只允许结构化选择和只读结果；查询生成器/执行器已有基础，但 audit、取消、超时、截断和权限结果尚未完成前，不得宣称查询验证 P0 完成。

## 1. 设计原则

1. 以业务 DataSource 为主视角，不把 Doris Catalog/DB 树作为首页。
2. Resource、Source、Target、Task、Lifecycle 状态分开，禁止合成一个含糊的“正常/异常”。
3. GET 页面只读；刷新按钮显式触发 Reconcile，并展示最近对账时间。
4. 危险操作先展示影响对象，再要求二次确认。
5. 能力不支持时保留入口但 disabled，并显示稳定 reason。
6. 复用现有 DataSource Card、PageHeader、Table、Drawer、Modal、Steps、Tabs 和任务页面，不复制组件体系。
7. P0 页面不提供任意 SQL、自动修复、表结构在线 ALTER 或 Script 湖任务入口。

## 3. 跨页面状态语义

### 3.1 Resource Status

| 状态 | 展示 | 色义 | 可操作 |
|---|---|---|---|
| CREATING/PENDING_CREATE | 创建中 | processing | 查看、刷新 |
| READY | 已就绪 | success | 正常操作 |
| ERROR/CREATE_FAILED | 创建失败 | error | 查看错误、重试 |
| MISSING | 实际资源缺失 | error | 对账、按管理等级重试 |
| DELETING | 删除中 | processing | 只读 |
| DELETED | 已删除 | default | 查看历史、重新创建 |

### 3.2 Consistency Status

```text
CONSISTENT  一致
DRIFT       已漂移
MISSING     缺失
UNKNOWN     未知/远端不可用
UNBOUND     未关联任务（仅 Task）
```

所有 Tag 旁有 Tooltip；不能只靠颜色表达。

### 3.3 页面通用状态

- 首屏 Loading：Skeleton/Spin，不闪 Empty；
- Empty：说明前置条件并提供唯一主操作；
- API Error：Alert + Retry；
- Partial：列表可展示，失败维度显示 UNKNOWN 和原因；
- Permission Denied：禁用操作并说明所需权限；
- Reconcile：按钮 loading，不清空现有数据；成功后重新 GET；
- 长错误默认折叠，提供复制脱敏 error code/message。

## 4. DataSource 页面接入

现有 DataSource Card/List 增加“数据入湖”操作组：

```text
智能推荐
物理入湖
逻辑入湖
```

### 4.1 智能推荐 Modal

宽度约 720，内容分两区：

- 顶部能力：物理/逻辑是否支持及 disabled reason；
- 四个 Yes/No 问题；
- 结果：推荐模式、原因、其它模式仍可选。

主按钮“按推荐方式继续”；次按钮“选择其它方式”。推荐不落库。

### 4.2 入口行为

- 物理入湖：跳 `/lake/resources/{dataSourceId}`；无 Binding 时展示建库 Empty State。
- 逻辑入湖：先读 capability；支持则打开创建向导，不支持则 Modal 展示缺失 Driver/网络/类型原因。
- Metadata Binding 未 READY：物理入口 disabled，提供“前往探查”。

## 6. 物理入湖详情 `/lake/resources/:sourceDataSourceId`

### 6.1 Header

面包屑：物理入湖 / DataSource 名称。

左侧：单位、系统、源类型、DataSource 状态。右侧：

```text
[显式对账] [创建 ODS 表]
```

下方显示：ODS Database、Resource Status、最近对账时间。失败时 Alert 显示 code/message 和“重试建库”。

### 6.2 Tabs

```text
ODS 资源
关联引接
操作记录
```

#### ODS 资源

分两块：

1. 已登记资源表；
2. 发现的未纳管表。

已登记列：

| 源表 | ODS 表 | 管理等级 | Resource | 生命周期 | Source | Target | Task | 操作 |
|---|---|---|---|---|---|---|---|---|

操作按等级：

- MANAGED：详情、创建/查看引接、重试、删除；
- AUTO_CREATED：详情、查看引接、重试、删除；
- linked UNMANAGED：详情、解除关联；
- discovered UNMANAGED：查看实际结构、关联源表。

#### 关联引接

两个子区：

- TABLE Relations：任务、版本、运行类型、目标表、Schema Mode、关系状态、上线/调度状态；
- NAMESPACE Relations：明确提示“动态任务产生的表按未纳管发现，不自动猜测源表”。

#### 操作记录

显示 Operation Type、资源、Generation、状态、操作者、开始/完成时间、脱敏错误。

## 7. 创建 ODS Database

使用 ModalForm：

- DataSource、单位 code、系统 code 只读；
- 固定前缀 `ods_{unit}_{system}_` 只读；
- 用户只输入 custom name；
- 实时显示完整名称与 64 字符计数；
- code 缺失/非法时不出现提交按钮，提供“前往主数据维护”。

提交后 Modal 保持 operation 状态；成功进入详情，失败显示 error code 和 Retry，不假装本地事务可回滚 Doris。

## 8. MANAGED ODS 四步向导

使用独立页面或宽 Drawer，推荐独立页面，避免字段较多时拥挤。

### Step 1 选择源表

- 左侧 OM Database/Schema 树；右侧 Table；
- 搜索表名；
- 展示字段数、PK 状态、最近探查时间；
- 已存在有效 Mapping 的 Table disabled，并显示目标表。

### Step 2 表结构

顶部：目标表名、表模型 Duplicate/Unique。

字段表：

| Key | 源字段 | 源类型 | Nullable | 目标字段 | 目标类型 | 目标 Nullable | 提示 |
|---|---|---|---|---|---|---|---|

规则：

- 非 Key 默认 STRING；
- 选为 Key 时若当前是 STRING，自动切换为 VARCHAR(255)并给可见提示；
- Key 不允许切回 STRING/FLOAT/DOUBLE；
- 目标字段名修改会进入 mappings；
- Duplicate Key 文案为“排序 Key”，不能叫主键；
- 归一化后重名立即行内 Error。

### Step 3 分区与生命周期

开关“时间分区”；关闭时生命周期只能永久。

开启后：

- 字段 Select 只显示 source+target 均 NOT NULL 且目标为 DATE/DATETIME；
- 粒度 DAY/MONTH/YEAR；
- 生命周期：永久 / 使用策略 / 自定义历史分区数；
- Unique 分区字段不在 Key 时阻止下一步；
- 固定解释 retention 是历史分区数，不是精确自然日 TTL。

### Step 4 Preview

四个区：

1. Source Summary；
2. Target Contract Summary；
3. Warnings/Errors；
4. 折叠 DDL Preview。

Errors 非空禁用创建；Warnings 需要勾选“已了解写入转换风险”。创建使用 previewToken，不回传并执行 DDL。

## 9. ODS Table 详情 `/lake/resources/table/:mappingId`

Header：Source → Target、管理等级、Resource Status、三个一致性 Tag。

Tabs：

```text
基本信息
表结构
分区与生命周期
数据引接
一致性
操作记录
```

### 9.1 表结构

MANAGED：Desired/Actual 切换或并排 Diff；默认只显示差异。AUTO/UNMANAGED 只显示 Actual。

### 9.2 分区与生命周期

- Structural Auto Range；
- desired retention；
- actual retention；
- 历史/当前/未来分区数量；
- 最后观察时间；
- 未预分区时“应用生命周期”disabled。

retention 减小弹窗展示“预计将超出保留范围的历史分区”，用户输入目标表名确认。

### 9.3 数据引接

- 关联任务列表；
- “创建引接任务”跳转现有单表任务并预填 Binding、target、mappings；
- Drift relation 展示 snapshot/current Diff；
- 删除表前要求所有 ACTIVE 任务下线或改写。

### 9.4 一致性

三个独立 Panel：Source、Target、Task。UNKNOWN 展示远端不可用原因，不能显示为缺失。

## 12. 结构化只读查询验证

不显示 TextArea SQL 编辑器。

### 12.1 单表验证

- Catalog/DB/Table 只读选择；
- 字段多选；
- Limit 固定 1–100，默认 10；
- 先 EXPLAIN，可执行后显示结果、耗时、截断信息。

### 12.2 跨 Catalog JOIN

左右两侧分别选择 Catalog/DB/Table；选择 Join Key 和返回字段；只支持 INNER/LEFT 与等值条件；生成 SQL 只读展示。

结果区必须支持：Loading、Timeout、Canceled、Truncated、Permission Denied、Unsupported Type。

## 13. 删除确认

### 13.1 Table

确认 Modal 先请求 impact API，展示：

- 实际 Doris 表及是否存在；
- ACTIVE/ONLINE/调度任务；
- 生命周期；
- 数据不可恢复提示。

存在可再次运行任务时主按钮 disabled。满足条件后要求输入目标表名。

### 13.2 Database

只有无有效 Mapping、无 Namespace Relation 时允许；不提供 Cascade。

### 13.3 Catalog

固定提示：“该操作仅删除 Doris 中的逻辑挂载关系，不会删除源数据库数据。”
